# Sherif Morsi

Portfolio of Sherif Morsi, a third-year Computer Science student at Concordia University in Montreal: AI for long-term investing, quant research, and AI agents.

**Live:** https://shmorsi.github.io/

The site shows **three projects**: Deep Portfolio Constructor (AI for long-term investing, in three studies), a time-series foundation model built from scratch, and Aurvane (a trust layer for AI agents). `scripts/groups.py` is the one place that says which study belongs to which project and how each is numbered. The site is a **master page plus one page per study**. The master page features the Deep Portfolio Constructor as an interactive lab, then one card per project, each with a chart drawn from that project's committed results (two of them interactive). Each card links to the project's own page, with the method, the results, the limits and links to the code.

## Keep the site in sync with the projects

Change a project in its own repository first, merge it to that repository's `main`, then bring it here. One command does every step below, in order, and stops on the first problem:

```sh
python3 scripts/sync_all.py          # expects the project repos checked out next to this one (--src to point elsewhere)
```

It copies what each project generates (the Deep Portfolio Constructor's `reports/site_wealth.json` and, for the Pension Lab that lives in the same repository, `reports/pension/site_pension.json`; Aurvane's page, `ui/site/index.html`, and its benchmark summaries), checks every hand-written TSFM and World Shock Lab figure against the raw numbers in the JSON file it cites, counts World Shock Lab's live score files into its page (`sync_wsl_live.py`), then rebuilds and runs `check_site.py`. Exit 0 means the site matches every project.

The [Sync projects](.github/workflows/sync.yml) workflow runs the same script daily against each project's `main` (or on demand from the Actions tab) and opens one pull request, `auto/sync-projects`, when anything changed. It never merges by itself. If a hand-written figure went stale it fails instead, and the run summary names the stat and the page to fix. It needs one setting: Settings > Actions > General > "Allow GitHub Actions to create and approve pull requests".

To keep merges clean: one branch per change, merged to `main` before starting the next; project repo first, site second; never edit a generated file (`index.html`, `projects/deep-portfolio-constructor.html`, `projects/pension-lab.html`, `aurvane/index.html`, `data/dpc_wealth.json`, `data/pension.json`) by hand, because the next sync overwrites it.

For one page on what lives where, what runs by itself and what waits for a person, see [MAP.md](MAP.md).

## Update a measured number

Do not type a new figure into a page. Every displayed figure, and every chart on the master page, is read from **[data/projects.json](data/projects.json)**, and each figure names the committed result it came from. `scripts/check_site.py` fails if the visible fallback text drifts from that file, or if the master page no longer matches a fresh build.

The project repositories generate their own documents from those result files. Copy a figure into `data/projects.json` only when a command printed it from a committed file, and keep the source path on the stat. Do not round it again here.

## Build

The master page, the Deep Portfolio Constructor page and the Pension Lab page are generated from `data/projects.json`, so their fallback text always matches the data. The TSFM and World Shock Lab pages are hand-written, and Aurvane's comes from its own repository; `sync_chrome.py` keeps the shared parts of all of them in step.

```sh
python3 scripts/sync_dpc.py ../deep-portfolio-constructor/reports/site_wealth.json    # project figures, series and holdings, when they change
python3 scripts/sync_pension.py ../deep-portfolio-constructor/reports/pension/site_pension.json   # the Pension Lab, when its results change
python3 scripts/sync_wsl_live.py ../world-shock-lab    # World Shock Lab's live scores, when a decision is scored
python3 scripts/sync_aurvane.py ../aurvane/ui/site/index.html   # Aurvane's page, when its demo or results change
python3 scripts/sync_risk.py ../deep-portfolio-constructor/reports/risk/site_risk.json   # the risk study, when its results change
python3 scripts/make_marks.py        # one project mark per project (assets/marks/)
python3 scripts/make_land.py land-110m.json   # data/land_mask.json for the particle globe (only if the map source changes)
python3 scripts/build_home.py        # index.html, the master page (with scripts/ride.py, scripts/worlds.py, scripts/stories.py and scripts/plain.py)
python3 scripts/build_dpc_page.py    # projects/deep-portfolio-constructor.html
python3 scripts/build_pension_page.py   # projects/pension-lab.html
python3 scripts/sync_chrome.py       # header, footer, project label, plain-English panel, previous / next links, private-repo notes, and the version stamp on site.css and site.js (run it after editing either)
python3 scripts/make_og.py           # share images (needs Playwright's Chromium)
python3 scripts/check_site.py        # copy rules, figure binds, charts, pending slots, internal links
```

## Design

Static HTML, one stylesheet (`assets/site.css`), one script (`assets/site.js`), and a self-hosted Inter Tight under the SIL Open Font License. No third-party font request, no framework.

The look is a night journey across an illustrated Earth, for a deep learning and markets portfolio: night by default on every page (day in the light theme), tracked uppercase display type, thin rules, telemetry numerals, ghost buttons that fill on hover, and one ice-blue accent (`#8ec5ff`), with amber for anything live. The header toggle switches to light for that browser.

- **The story.** The site is told as one long voyage, because investing for decades is one: it has a promise at the end of it (pensions to pay) and four machines that get it there (the engine that grows the money, the navigator that sees ahead, the weather station that measures storms, the shield that protects the crew), one project each. The frame is for readers outside finance and tech; the explanations under it stay literal and plain.
- **The land.** Earth is the setting on every page: one journey by train, drawn in code ("The land" in `assets/site.js`; nothing in it is an image, so the whole world weighs a few kilobytes and is sharp at any size). The line crosses high mountains on a stone viaduct (the engine), farmland with its houses (the promise), a coast with a lighthouse and a weather mast (the weather station), a plain of wind turbines under an observatory (the navigator), then a colourful city (the shield), and ends at a station. Every ridge, tree, arch, carriage and window is a shape placed by a seeded rule.
- **It follows the scroll.** The camera travels as the page goes down and eases as each chapter arrives; the train keeps a little ahead of it; the turbines, the big wheel and the lighthouse beam turn with the scroll; the time of day moves on. Nothing runs on a timer: stop scrolling and the land stops. Behind a chapter's words the land is veiled, behind running text it is washed back, and the last screen of every page is left to it, so the footer stands on the ground. A project page stays in its own stretch of the line. Where the opening picture sits above the words (phones, tablets) the land is a banner in that box. Under reduced motion it is one still, quiet strip.
- **A chapter stands still and its place moves.** While a chapter is pinned, the page does not scroll and the reader's scroll drives two things: the points re-form into the chapter's pictures, and the land answers. The train crosses the viaduct; windows come on in the farmhouses and a balloon climbs; a storm builds over the bay, lightning strikes twice, and it clears; the observatory throws a line that widens into a range; the city lights up floor by floor. On the last screen the train pulls into the station.
- **Arrival, depth, and the route.** When a page opens the land comes up, the moon rises and the train rolls in (once, about two seconds). The land leans a little with the pointer. On wide screens a route runs down the right edge: a stop for each place, a marker where the reader is, and a link on each stop (to its chapter on the master page, to its page from a project page), so the whole line stays in view.
- **The land carries the results.** Each chapter has a halt on the line: a platform and a board with the place's name and the project's headline number, read from the strip under the opening screen. The engine's mountain is its result: the crest of that ridge is the growth of one dollar from 1960 to 2026, the same line as the chapter's chart, read from the page's own picture; every real drawdown cuts a gully in it. The contact block is a ticket for the end of the line, from Montréal to the reader's team.
- **Night and day.** The dark theme is the night: the land's sky is clear, so two still layers of stars and a slow nebula are the sky, windows and the train are lit, and the moon is out. The light theme is the day: the land paints its own sky and the sun is out. The header toggle switches between them.
- **Hero.** Full-bleed: the name on the left, and beside it the moon rising behind the mountains (the sun by day), ringed by 18,000 glowing points (8,000 on phones) that gather from the stars when the page opens, shimmer with travelling light, and lean toward the pointer. The moon is drawn with the land, so the peaks pass in front of it.
- **The stage.** Those points are one system for the whole page (a WebGL canvas fixed behind the content, "The stage" in `assets/site.js`). As the reader scrolls they leave the rings and re-form into each story's picture in turn: "$1", thirty industry bars, the growth of that dollar drawn from 1960 to 2026, a pension plan's $90 against the $100 it has promised and then twenty years of its simulated futures under three ways of investing, a forecast and its range, a globe taking a shock that spreads out from Washington, thirty attacks landing and then being stopped, and finally the name. Each shape is sampled from the story's own SVG, so the points carry the same data and the SVG keeps its words and numbers on top; the globe's land comes from `data/land_mask.json` (Natural Earth 1:110m, public domain; `scripts/make_land.py` rasterises it). Without WebGL, or under reduced motion, the SVG pictures stay as they are.
- **Every project page opens with its picture.** `scripts/sync_chrome.py` puts the project's scene (the same one as its story, in its final state) beside the page title, and the stage draws it in points when the page loads: the growth line draws itself on the portfolio page, the bars fill on the forecasting page, the shock spreads over the globe on the World Shock Lab page. Without the script it is a plain, finished SVG figure.
- **The points respond.** They part around the pointer, trail a little behind a fast scroll, lean with a slow idle sway so the depth shows without a mouse, and take each chapter's colour (ice, amber, violet, teal, rose). If a device cannot hold the frame rate the stage first drops to standard resolution, then thins the points (every shape is stored in one shuffled order, so drawing fewer points thins each picture evenly). It never asks for more than 18,000 points on a desktop or 8,000 on a phone.
- **Telemetry strip.** Each project's headline figure, linked to its card.
- **The ride: one dollar, 1960.** The first thing under the opening screen, and the one thing the reader does rather than reads. Pick a train (hold the market, a momentum rule, or the wealth study's neural network), board, and ride it through every month since January 1960. The ground under each train is what its dollar had become, on a scale where equal growth is an equal climb, and the camera follows the reader's train, so a crash is felt as a fall. The market's real falls of a fifth or more arrive as storms with their depth (found from the series by `scripts/ride.py`; only their everyday names are typed), the other two trains run alongside, and past today there is only fog. At the arrival stand the three results and the verdicts of the test fixed in advance: one gap is real, and the network's cannot be told from luck. That finding is the site's whole story, and the stops after it (the five worlds, then the chapters) are its details: a storm links to World Shock Lab, the fog to the forecasting model, the guard on board to Aurvane, the end of the line to the Pension Lab.

  `scripts/ride.py` writes the section, takes every month from `data/dpc_wealth.json` (the file the portfolio page's chart reads), and stops the build if a journey does not end on its published figure; the final figures shown are the published ones. It plays only when asked, can be paused and dragged with the slider (which the keyboard also moves), and never looks ahead: a carriage leans with the grade behind it. Under reduced motion "Board" goes straight to the arrival; without JavaScript the section is its words and the three results. The opening screen's main button leads to it.
- **The route: five worlds, one line.** After the ride the whole site is visible at once: every project is a world hanging over the land, a railway runs past all five, and the train on it follows the scroll (and goes to whichever world the reader points at). Each world is drawn from its project's results, and a card under it gives the headline figure, the result in a sentence, and what the drawing shows:
  - *The engine:* the ridge around the world is the growth of one dollar from 1960 to today (a seam every ten years); the dashed line inside it is the market.
  - *The promise:* each mark in its rings is one simulated pension plan, placed by where it stands after 20 years, under the learned policy (bright) and the usual rule (dim); the thin line is fully funded.
  - *The weather station:* the Earth, lit where the sun is at this minute (worked out from the clock, no request to anywhere), with a wave leaving Washington, and the days left to the next forecasted decision.
  - *The navigator:* the dashed ring is the standard method; the model's ring sits inside it by exactly its test error, and is as wide as its 95% interval.
  - *The shield:* thirty attacks arrive in each round; the ones that land are the ones the benchmark file says land.

  `scripts/worlds.py` writes the cards (every figure a data-bind) and hands the drawing its numbers from the files the chapters use; it stops the build if the growth series and the headline disagree, or the benchmark file and the page do. The drawing ("The route" in `assets/site.js`) is one 2D canvas, painted only while it is on screen, with a Pause button. Under reduced motion it is one still frame; without JavaScript the section is the five cards. It replaces the three-column list that used to open the voyage.
- **Featured project: the portfolio lab.** Pick one of seven long-only strategies and see its growth of $1 since 1960 (market crashes shaded, a readout under the pointer), its compound growth, worst fall and turnover, its pre-registered verdict against the market, and what it did differently, in plain English. Beside its deep stack sits the interactive illustration of end-to-end learning: seeded random-walk prices stream into a small network, the outputs set the portfolio's weights, and amber pulses run backwards as the gradient. Point at a stock to trace it; click its price line to shock it. It is labelled as an illustration, not data, has a pause button, and draws one still frame under `prefers-reduced-motion`.
- **Project cards.** One chart grammar for every card: a reference line (zero or the baseline) and either bars or points with their intervals, drawn from the data at build time. World Shock Lab's card takes a Fed or Bank of Canada surprise of any size and scales the committed per-10 bp estimates and their 90% bands; Aurvane's card replays its 30 poisoned tasks with and without the guard.
- **The portfolio page.** "Try it" is a two-asset growth toy (labelled as made-up numbers) that shows why the network is trained on the growth of wealth rather than on average return; "Inside the portfolio" scrubs through the network's real holdings against the market's, quarter by quarter since 1960; "How often to trade" switches the same trained network between daily, monthly, quarterly and yearly rebalancing; the results compare it with the S&P 500 (dividends reinvested) and the NASDAQ Composite.
- **Plain English.** Jargon (Sharpe, the Kelly criterion, active share, CRPS, basis point, prompt injection and so on) has a dotted underline and a one-tap definition.

- **Three projects, five chapters, in plain English.** Right after the hero, a sentence lights up word by word as you scroll, then each project gets a pinned chapter: the screen holds while four short, jargon-free steps (the question, what it does, how it works, the honest result) play out with the scroll, and a picture beside them builds from the project's real results: the growth of $1 since 1960 drawn month by month, the forecast error against a standard method, a Fed surprise rippling across 53 markets, 30 attacks landing and then being stopped. The words live in `scripts/plain.py` (one source, also used for the "In plain English" panel at the top of each project page); the pictures are drawn by `scripts/stories.py` from `data/projects.json` and `data/dpc_wealth.json`, and every number in them is a data-bind.
- **Motion that follows the scroll.** Nothing waits on a timer: titles rise letter by letter, blocks slide into place and figures count up as a function of the scroll position, so the page moves exactly as fast as the reader. The mouse wheel is smoothed. A slow WebGL field of domain-warped noise sits behind every page and takes on each chapter's colour; the hero name thickens and lights toward the pointer, then leaves letter by letter as you scroll; a toolkit marquee runs with the scroll; a closing wordmark fills as the page ends. Panels light up under the pointer, buttons lean toward it, and pages cross-fade.

All of it lives at the end of `assets/site.css` and `assets/site.js` ("Atmosphere"). It is added only when the reader allows motion: under `prefers-reduced-motion` the field draws one still frame, the chapters lay out as plain text beside finished pictures, and nothing moves. Nothing is hidden if the script does not run.

Every interactive piece is rendered as complete static HTML first by `scripts/lab.py`, so it reads correctly without JavaScript; `assets/site.js` then wires it up.

Project pages share one template: a project label with its mark, the headline, a sticky section index built from the page's own headings, the sections, and previous / next project links. Motion is a short fade on scroll and charts that draw in; nothing moves under `prefers-reduced-motion`, and nothing is hidden if the script does not run.

`aurvane/index.html` is a project page like the others. The `aurvane` repository builds its demo (`python ui/build.py` there writes `ui/site/index.html`: the replay, the try-it box, the picture suite, the results, with their styles and scripts), and `python3 scripts/sync_aurvane.py <path to ui/site/index.html>` brings it here. The page loads this site's stylesheet and script, so its header, sky, type, colours and themes are the site's own; its styles use this site's tokens and are scoped to the demo. `sync_chrome.py` writes the header, footer, project label, the "In plain English" panel, the picture and the previous / next links into it, as on every project page, and `check_site.py` fails if the page defines a palette of its own or is not dressed. World Shock Lab's app (`shock-lab/`) carries the same header: every page of every project opens under one header.

## Check

```sh
python3 -m http.server 4173      # preview at http://localhost:4173
python3 scripts/check_site.py    # copy rules, figure binds, charts, pending slots, and internal links
python3 scripts/check_layout.py  # every chapter fits its screen (needs: pip install playwright && python -m playwright install chromium)
```

**Chapters fit the screen they are pinned to.** Each chapter of the master page holds the screen while its steps play, so its words, its button and its picture all have to fit one screen. Type follows the screen's height as well as its width, the picture is fitted into the room that is left, the intro line is dropped on a short laptop screen, and a step longer than 300 characters is set a little smaller (`scripts/stories.py`). A screen under 560 px tall (a phone on its side) gets the plain page, as under reduced motion. `scripts/check_layout.py` opens the built page in a real browser at 14 sizes, from a 360 px phone to a 2560 px desktop, scrolls to every step of every chapter and fails if anything is cut off, overlaps, or squeezes the picture below a sixth of the screen. CI runs it on every pull request.

The resume link points at `resume/Sherif_Morsi_Resume.pdf`. `bash resume/build.sh` builds it, and `resume/Sherif_Morsi_Resume_AI.pdf` (the same content with the forecasting model and Aurvane first, for AI and ML roles), from the one `.tex` file, and fails if either runs past one page. World Shock Lab's interactive app is part of this site, at `shock-lab/`: `scripts/sync_all.py` copies its build (`web/dist/` in the `world-shock-lab` repository, where it carries this site's header) file for file. `world-shock-lab/` holds one page that forwards the app's old address to `shock-lab/`.
